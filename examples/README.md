# Tempr agent examples

## Run an evaluation

Start Tempr using the [repository quickstart](../README.md#quickstart), then install the example dependencies and configure credentials:

```bash
cd examples
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
```

Set `OPENAI_API_KEY` in `examples/.env` for the agent. Tempr needs its own key in the repository root `.env` to classify, generate cases, and judge results. Set `TEMPR_API_URL` to use a different API URL.

Run the full workflow with five generated cases, or choose a count from 1 to 100:

```bash
python command.py task_manager
python command.py task_manager --count 10
```

Each invocation finds or creates the named platform agent, adds its next version, classifies it, generates a suite, runs each question with fresh agent state, uploads traces, and waits for judging. Polling reports status every second. The command prints the workspace link, scores, and runtime failures.

## Understand the structure

`task_manager/` contains only the task manager's definition and behavior: its name, prompt, model, tools, storage, and agent factory. Put agent-specific behavior in that directory.

`shared/` contains decisions made by this example runner: loading settings, finding an agent by name, incrementing its version, waiting for background jobs, running cases, recording traces, and printing results. These helpers compose the end-to-end workflow.

`tempr/` contains direct HTTP calls to the platform. Its LangChain integration converts prompts, tools, and messages to the configuration and trace shapes Tempr accepts. It does not choose versions or wait for jobs.

## Read the code

Start with `command.py` to see argument handling and the agent selection. Then read `shared/workflow.py` for the evaluation sequence and `shared/registry.py` to see how examples are selected. Read `task_manager/config.py` and `system_prompt.md` to understand what is registered, followed by `agent/agent.py`, `agent/tools.py`, and `agent/store.py` to see how it runs. Read `shared/versions.py` and `shared/polling.py` for workflow behavior; finish with `tempr/client.py` and `tempr/integrations/langchain.py` for platform requests and data conversion.

To add another example, create a sibling agent package with its own configuration, prompt, factory, and tools, then add its name to the choices and its definition in `command.py`.

Test cases are generated by an LLM and may differ between runs. Agent execution and Tempr classification, generation, and judging make model calls that may incur provider charges.
